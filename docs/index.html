Overview

The Abstraction and Reasoning Corpus (ARC) asks a model to infer a hidden grid-transformation rule from a handful of demonstration pairs, then apply it to a new input. With only a few examples per task, training data is the main bottleneck.

This project tests one question in a controlled way: how much does procedurally generated, rule-verified training data help a transductive solver on ARC-AGI-1, and where does it stop helping? Each experiment changes one variable against a fixed baseline. Every score is re-verified against the evaluation solutions and corrected for a train/eval collision the audit turned up.

On top of that base, the project explores inference-time methods: orientation canonicalization, rule-consistency candidate scoring, LoRA test-time training, DFS decoding with product-of-experts rescoring, and augmentation-invariant task embeddings.

Experiment sequence

Five numbered experiments, each measured against the one before it.

  1. 01 · Baseline 37.6%

    Trained on the original ARC-1 training tasks plus ConceptARC, with no synthetic data. Two independent runs (v2, v3) both land at 37.625% at the end of the WSD decay schedule. Every later experiment is measured against this.

  2. 02 · re-ARC generator swap 59.4%

    Same training setup, but each ARC-1 training task gets up to 12 synthetic pairs from the re-ARC procedural generators appended to it. This was the biggest single gain in the project: +21.75 points from the data change alone. The dataset builder (prepare_dataset_rearc.py) refuses to augment any task ID that appears in the evaluation set.

  3. 03 · cap=300 ablation 56.75% · regression

    Raising the per-task cap from 12 to 300 (about 2.4× more synthetic data) made the score worse. Flooding a task with synthetic variations of the same rule seems to dilute the training signal. The cap was not adopted. It is reported here because negative results are useful too.

  4. 04 · Schedule extension 61.5% raw · 61.25% adj.

    Keeping the 12-pair dataset and extending training from 650 to 750 to 1000 epochs showed the original schedule was cutting training short. The epoch-1000 checkpoint is the best model in the project.

  5. 05 · Data-leakage audit correction

    A systematic check of training and evaluation task IDs found one collision. Every reported number is corrected for it; see below.

Data-leakage audit

Task 070dd51e appears in both the 1,307-task training set and the 400-task evaluation set. The collision is in the underlying ARC-1 asset files, not something the augmentation pipeline introduced.

The key detail is that the baseline checkpoint does not solve it, and every re-ARC-trained checkpoint does. Generating many synthetic pairs for every training task ID, the leaked one included, makes the leak matter more. Extra exposure to the rule makes the eval instance easier to solve through familiarity rather than generalization. Credit for this task is removed from every reported score.

Inference-time prototypes

Exploratory work in experiments/06_prototypes/ and src/, built on top of the trained solver.

Orientation canonicalization

Scores each of the 8 dihedral orientations of a task by the model's loss on the demonstrations, then runs inference in the best one.

src/canonicalize.py

Rule-Consistency Scoring (RCOS)

A correct candidate output, added as an extra demo, should lower the model's uncertainty on the real demos. A wrong one should raise it. Candidates are ranked by that difference in cross-entropy.

src/rcos.py

LoRA test-time training

Per-task LoRA adapters trained on the demonstrations at inference time. The memorised task embedding is zeroed and re-learned so the adapters actually receive gradient.

src/lora_ttt.py

DFS + product-of-experts

Threshold-filtered depth-first decoding to generate more varied candidates, each rescored by summed log-probability across 16 augmented views (D8 × color permutations × demo orderings).

experiments/06_prototypes/prototype_poe/

Augmentation-invariant meta-encoder

Predicts a task embedding directly from its demo pairs. A consistency loss forces the same embedding across augmented views, which gives a warm start that does not depend on orientation.

src/meta_encoder.py

Checkpoint ensembling

Weight merging and output-level ensembling across checkpoints and seeds, pooling candidates before rescoring.

experiments/06_prototypes/merge_*.py

Reproduce

Every row in the results table can be regenerated. A single RTX 5090 (or equivalent) trains the 1000-epoch run in a few hours. flash-attn needs CUDA ≥ 12.8.

git clone https://github.com/Abhijeet399/procedural-augmentation-arc.git
cd procedural-augmentation-arc
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# Base data
cd dataset_building_scripts
python download_and_group.py
python build_datasets.py arc1 --add-conceptarc --with-filtered
cd ..

# Combined ARC-1 + re-ARC dataset (12 pairs/task cap)
python dataset_building_scripts/prepare_dataset_rearc.py \
    --orig-challenges assets/challenges.json \
    --rearc-tasks-dir assets/re_arc/tasks \
    --eval-solutions assets/solutions.json \
    --max-rearc-pairs-per-task 12 --seed 42 \
    --out-challenges assets/combined_rearc_challenges.json

# Best model (epoch 1000)
python experiments/04_schedule_extension/run_epochs1000.py high

# Audit
python experiments/05_leak_audit/leak_check.py \
    --train-challenges assets/challenges.json \
    --eval-solutions assets/solutions.json

See REPRODUCE.md for the command behind every experiment, and results/ for full per-checkpoint sweeps and the exact list of solved tasks behind each score. Checkpoints (~590 MB each) are not committed.
